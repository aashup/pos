# Zazzy POS — React Native Windows (`desktop-react/`)

Full-featured restaurant POS built with React Native targeting Windows via `react-native-windows`. Identical feature set to the Electron desktop app and the Expo mobile app — all backed by the same Laravel API.

---

## Three-Layer Data Architecture — THE GOLDEN RULE

```
Layer 1: State     → Zustand        (in-memory, real-time UI state only)
Layer 2: Local DB  → WatermelonDB   (offline-first; THE source of truth for all reads)
Layer 3: Master DB → Laravel API    (server source of truth; sync target)
```

**Rules — identical to mobile-app:**
- All UI reads from WatermelonDB — never from TanStack Query cache
- All mutations write to WatermelonDB first (`sync_status='pending'`), then fire-and-forget push to API
- API pull syncs upsert into WatermelonDB; skip rows where local `sync_status === 'pending'`
- Reports computed from WatermelonDB aggregations (offline-capable)
- Inventory CRUD writes local first, pushes API in background

## Key Differences from `mobile-app/`

| Concern | mobile-app (Expo) | desktop-react (RN Windows) |
|---------|-------------------|---------------------------|
| Router | Expo Router (file-based) | React Navigation (stack + tabs) |
| Storage | `react-native-mmkv` | `@react-native-async-storage/async-storage` |
| Auth hydration | MMKV sync read at startup | `initAuthStore()` async, called in `App.tsx` |
| Background sync | `AppState.addEventListener` + 30-min interval | 30-min interval only (Windows doesn't background-suspend) |
| Barcode scan | `react-native-vision-camera` | Removed (manual entry only) |
| QR scan for tables | Camera-based | Removed (click table directly) |
| DB name | `zazzy_mobile` | `zazzy_windows` |
| `pt-12` status bar offset | Present | Removed (no iOS status bar) |
| Native layer | Expo SDK 54 | react-native-windows 0.76 |

## How to Run

```bash
cd D:\erp\pos\desktop-react

# Start Metro bundler
npm start

# Run on Windows desktop
npx react-native run-windows
```

**Prerequisites for Windows:**
- Visual Studio 2022 with "Desktop development with C++" + "Universal Windows Platform development"
- Windows SDK 10.0.19041+
- Node 22+

## App Startup Sequence

1. `App.tsx` renders `<LoadingView />` immediately
2. `initAuthStore()` reads token/user/serverUrl from AsyncStorage into Zustand
3. `startSyncScheduler()` begins: `runAllSyncs()` immediately + 30-min interval
4. `setReady(true)` — `<LoadingView />` replaced by full app tree
5. `RootNavigator` checks `useAuthStore(s => s.token)` — routes to Login or Tabs

## Import Path Convention

All cross-module imports use the `@/` alias mapped to project root:

```ts
import { database } from '@/src/db';
import { useAuthStore } from '@/src/store/authStore';
import type { MainStackParamList } from '@/navigation/types';
import SalesScreen from '@/screens/reports/SalesScreen';
```

**Never** use `@/db`, `@/store/`, `@/lib/` — these are the mobile-app paths (Expo) and will fail to resolve.

## Sync Engine (Windows-Specific)

`src/lib/syncEngine.ts` — no `AppState` listener (Windows desktop apps don't background-suspend):

```ts
export function startSyncScheduler(): void {
  runAllSyncs().catch(() => {});
  syncIntervalId = setInterval(() => runAllSyncs().catch(() => {}), 30 * 60 * 1000);
  // No AppState listener needed on Windows
}
```

---

## Auth Store (Windows-Specific)

`src/store/authStore.ts` — uses AsyncStorage instead of MMKV:

```ts
// MMKV has no Windows native module.
// Must call initAuthStore() before render — it's async.
export async function initAuthStore(): Promise<void> { ... }
```

Called in `App.tsx` before `setReady(true)`.

## WatermelonDB Schema

Schema version 2. 13 tables (LocationLog excluded — device-local only, not needed on Windows):
`items`, `item_groups`, `item_variants`, `modifier_groups`, `modifiers`, `floor_plans`, `dining_tables`, `orders`, `order_lines`, `kots`, `units`, `combos`, `combo_items`

DB file name: `zazzy_windows` (separate from the mobile `zazzy_mobile` DB).
